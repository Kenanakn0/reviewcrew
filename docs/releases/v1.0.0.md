# ReviewCrew v1.0.0

First release of ReviewCrew, a GitHub App that reviews pull requests with three specialist
agents (security, performance and tests) running in parallel and posts one review with
inline comments and a summary.

## Highlights

- **Multi-agent review, orchestrated with plain `asyncio`.** Agents run in parallel with
  per-agent timeouts; one failing agent never stops the review. Findings are typed and
  schema-validated, merged across agents, thresholded and anchored to lines GitHub accepts.
- **Runs on a free local model.** The default setup uses `qwen2.5-coder:7b` through Ollama;
  the Anthropic API and any OpenAI-compatible endpoint are supported too.
- **Deterministic where it can be.** A rule-based secret scan reports hardcoded
  credentials on their exact line, off-topic findings are dropped in code, and the test
  reviewer gets the list of changed functions the PR's tests do not mention.
- **Safe by construction.** PR code is never run, PR content is treated as untrusted data,
  the bot only posts `COMMENT` reviews, and secret values are masked in everything it
  writes, including GitHub's new stateless installation tokens.
- **Production basics.** Redis queue with per-commit idempotency, per-PR token budget,
  `.reviewcrew.yml` read from the base branch, Docker Compose stack.

## Measured quality

`qwen2.5-coder:7b` (Q4_K_M, Ollama 0.40.5, about 70% on an RTX 4050 Laptop GPU), frozen
prompts, 3 runs per set, mean (min-max):

| All LLM agents | Precision | Recall | F1 | False positives on clean cases per run |
|---|---:|---:|---:|---:|
| Tuning set (26 cases) | 49% (47-50%) | 100% | 65% (64-67%) | 8.3 on 5 cases |
| Held-out set (8 cases) | 37% (35-38%) | 100% | 54% (52-55%) | 4 on 2 cases |

With a 7B model roughly every second finding is a false positive, and precision drops on
cases the prompts were not tuned on. The cases contain one deliberate problem each, so the
recall is an optimistic upper bound. Details and per-case results: `eval/results.md`,
`eval/results_holdout.md`.

## Requirements

- A GitHub App you create yourself (see `docs/github-app-setup.md`) with *Pull requests*
  read & write, *Contents* read and *Metadata* read.
- Docker with Compose, or Python 3.12 with `uv` plus Redis 6.2+.
- An LLM: Ollama with a 16k context (`OLLAMA_CONTEXT_LENGTH=16384`), or an Anthropic API
  key.

## Known limitations

- Low precision with small local models (see above); larger hosted models were not measured.
- Agents see the diff plus a few surrounding lines, not the whole repository.
- Duplicate detection between agents is lexical.
- The secret scan and the untested-function hint are heuristics (regex based).
- GitHub only; one review per commit.
